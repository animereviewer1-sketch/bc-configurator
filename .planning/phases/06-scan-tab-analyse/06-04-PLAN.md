Planer-Probe (2026-09-19) — verbindliche Befunde:
1. **Größe des Exports:** Ein echter 28-Mod-Snapshot hat ≈ 18.700 Globals, 4.764 Assets (je bis zu 88 Allowlist-Felder), 120 Gruppen, 546 Patching-Einträge (05-CONSOLE-FINDINGS) — die JSON-Datei ist voraussichtlich mehrere MB groß. Sie darf NIE per Read/cat in den Agentenkontext geladen werden; Auswertung ausschließlich über `npm run analyze -- .planning/analysis/snapshot.json --limit N` (Markdown mit Zähltabelle + „neu“-Listen je Kategorie, Plan 06-03) und gezielte node-Einzeiler (z. B. Top-Präfixe der neuen Funktionen, Mod-Liste, Probe-APIs, Patching-Einträge mit ≥ 2 Mods).
2. **Export-Form (06-02):** `{ _meta: { version: 1, tool, exportedAt, snapshotId, counts: { globals, assets, groups, patching, mods } }, snapshot: { id, ts, gameVersion, modCount, mods: [{name, version}], sizeBytes, inventory } }`; `inventory.schema === 1`. `tools/analyze-snapshot.js` akzeptiert diese Form direkt.
3. **Badge-Regel (06-03):** globals/groups/patching/hooks → Name in der Menge aller Manifest-Bezeichner; assets → nach Gruppe; mods/probes → `modProbes` (bcx/lscg/mbs/themed/wce). „neu“ heißt: das Tool referenziert den Namen heute nirgends — nicht: „sicher nutzbar“. Bezeichner-kind im Manifest ist heuristisch (function/assetGroup/unknown).
4. **Was das Tool heute kann (für die Lückenanalyse):** Bot-Editor mit Triggern (Chat-Nachrichten, Events), Aktionen (Items anlegen/entfernen/sperren: `InventoryWear`/`InventoryRemove`/`InventoryLock`, Chat senden: `ChatRoomSendChat`/`ServerSend`, `CharacterRefresh`), Tabs Items/Outfit/Curse/Locks/Shop/Rang/Money/Inventar/Spieler/Variablen/Log; die Baseline listet exakt die referenzierten Namen (06-01-SUMMARY `counts`). BOT-DOKU.md beschreibt Trigger-/Aktionstypen — Vorschläge müssen daran anschließen (welche Aktion/Trigger-Klasse würde die Funktion füttern).
5. **Out of Scope (REQUIREMENTS.md):** „Automatisch generierter Bot-Code ohne Review“ und „Automatisches Aufräumen/Pruning von Snapshots“ — das Dokument enthält deshalb keine Code-Vorlagen und schlägt keine Auto-Löschung vor.
6. **Vergleichspräzedenz:** MBS „neue Items in dieser BC-Version“-Screen (FEATURES.md) — validiert die Diff-Sicht, nicht das Format.
